# ListenFlow 第二批通信基础设施阶段报告

日期：2026-10-19  
开发分支：`feature/native-communication-infrastructure`  
第一批基线：`816ec27a3b6ce21e21ed1cfd9a1af3a1fe3be694`

## 完成范围

1. 建立独立 `ListenFlow.Protocol` 项目，统一定义版本化消息、UTF-16 偏移、会话、快照版本、命令序号和播放代次。
2. 建立独立薄型 `ListenFlow.NativeHost`。宿主只处理原生消息帧、主程序启动、管道转发、断线通知和重连，不创建语音引擎。
3. 在唯一 ListenFlow 主程序中加入当前用户命名管道服务，并把命令路由到原有 `ReaderController`。
4. 将真实 `ReaderChangedEventArgs.SpokenRange` 映射为 `progress` 消息；没有使用定时器估算进度。
5. 对重复命令、旧会话、旧快照、非法 UTF-16 边界和管道发送失败返回明确错误。
6. 宿主发送失败后不自动重放开始、定位或停止命令；下一条新命令负责触发重连。
7. 增加真实进程通信探针，用于验证自动启动、单实例复用、真实语音进度、断线通知和错误恢复。

## 关键文件

- `ListenFlow.Protocol`：协议模型、验证和长度前缀传输。
- `Communication/DesktopCommandRouter.cs`：命令序列、会话和快照隔离，播放事件回传。
- `Communication/DesktopPipeServer.cs`：当前用户命名管道服务和连接生命周期。
- `ListenFlow.NativeHost`：独立原生消息宿主。
- `ListenFlow.CommunicationProbe`：真实进程验证工具，不属于产品播放核心。
- `test-communication.ps1`：通信测试入口。

## 测试结果

- Release 构建：0 个警告、0 个错误。
- 通信专项自动化测试：17 项通过。
- 完整回归：41 项通过，其中 3 项为真实 `Microsoft Xiaoxiao` SAPI 集成测试。
- 真实进程探针：通过。

真实进程探针确认：

- 宿主在主程序未运行时自动启动一个 ListenFlow 进程。
- `hello` 握手成功。
- `start` 返回真实 SAPI 进度 `0+1`。
- 暂停后定位到 UTF-16 位置 180，保持暂停；继续后从 `180+1` 开始回传真实进度。
- 停止返回 `stopped`。
- 第二个宿主复用同一桌面进程。
- 测试进程被中断后，宿主返回可恢复的 `pipe_disconnected`。
- 下一条新命令启动新的桌面进程并恢复连接。

## 已知限制与边界

- Edge 扩展、网页右键菜单、网页正文提取、网页原文高亮和网页左键定位尚未实现。
- Native Messaging 注册清单将在 Edge 扩展阶段根据最终扩展标识生成；当前没有修改注册表。
- 当前管道面向一个活动宿主长连接，断开后接受下一连接，符合单浏览器宿主模型。
- 本阶段没有生成正式安装包或正式发布版本。
- 第一批独立播放控制验收工具不高亮正文的限制已经单独记录，不影响播放核心。

## Edge 阶段的硬性验收条件

- 右键启动网页朗读。
- 高亮直接显示在网页原文上。
- 高亮由 `progress` 中的真实 SAPI UTF-16 范围驱动。
- 左键点击有效正文后发送新的定位命令，旧声音立即停止，高亮跳到新位置。
- 暂停、继续、停止和连续点击时，声音、会话、播放代次和高亮保持一致。

在上述浏览器内测试完成前，不得宣称网页高亮已经实现。
