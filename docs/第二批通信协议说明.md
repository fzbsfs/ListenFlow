# ListenFlow 本地通信协议第 1 版

## 传输与边界

- Edge 原生消息与本机命名管道统一使用四字节小端长度前缀，正文为 UTF-8 JSON。
- 单条消息最大 8 MiB，正文快照最大 5,000,000 个 UTF-16 代码单元。
- 所有网页正文位置均使用 UTF-16 半开区间；偏移不得切断代理项。
- 命名管道名为 `ListenFlow.Desktop.Protocol.v1`，服务端限制为当前 Windows 用户。
- 原生消息宿主不包含语音引擎，只负责消息转发、启动主程序和断线恢复。

## 命令

| 类型 | 必要字段 | 行为 |
|---|---|---|
| `hello` | `requestId` 可选 | 获取主程序状态与能力。 |
| `start` | `sessionId`、`snapshotId`、`snapshotVersion`、`commandSeq`、`text`、`offset` | 设置网页正文快照并从指定位置朗读。 |
| `pause` | `sessionId`、`commandSeq` | 暂停当前会话。 |
| `resume` | `sessionId`、`commandSeq` | 继续当前会话。 |
| `stop` | `sessionId`、`commandSeq` | 停止当前会话。 |
| `seek` | 会话、快照、版本、序号和 `offset` | 保持当前播放状态并原子定位。 |
| `ping` | `requestId` 可选 | 检查连接存活。 |

## 返回消息

| 类型 | 说明 |
|---|---|
| `ready` | 主程序已连接，并报告当前状态和能力。 |
| `ack` | 命令已由主程序播放状态线程执行。 |
| `state` | 播放状态、全局位置和播放代次变化。 |
| `progress` | 来自 SAPI 真实进度事件的 UTF-16 位置与长度。 |
| `error` | 带稳定错误码、说明和是否可恢复。 |
| `pong` | `ping` 回复。 |

## 过期消息隔离

- 同一播放会话中的 `commandSeq` 必须严格递增；重复或乱序命令返回 `stale_command`。
- 定位命令必须匹配当前 `snapshotId` 和 `snapshotVersion`；旧快照返回 `stale_snapshot`。
- 播放事件携带 `playbackGeneration`，Edge 后续必须丢弃旧代次事件。
- 管道发送失败后，宿主明确返回错误，不自动重放开始、定位或停止命令。调用方只能使用新的命令序号重新发起。
