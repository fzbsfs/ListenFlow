# 语音切换位置研究记录

目标是在不漏读、不重复已经听到内容的前提下立即切换语音。本记录不把该目标视为已经实现。

## 已取得的证据

- 当前控制器使用最近一次语音进度事件的原文起点作为续读位置。它可以保守避免跳过当前范围，但该范围已经发声的部分可能重复。
- 在本机英文系统语音上，将 `4003` 输出到内存音频流时，实际收到四个进度事件，原文位置和长度均为 `0` 和 `4`，音频位置分别约为 137、488、1122、1315 毫秒。不能将任意一个事件的原文末尾视作整个数字已经播放完毕。
- 微软说明多个读音可能对应相同的数字字符位置：[进度事件音频位置](https://learn.microsoft.com/en-us/dotnet/api/system.speech.synthesis.speakprogresseventargs.audioposition?view=net-10.0)。
- 微软说明语音标记事件在某些缓冲场景下可能早于实际听到相邻文字：[语音标记事件](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms723584%28v%3Dvs.85%29)。因此不能仅凭插入标记声称已解决扬声器实际播放位置问题。
- 使用系统默认音频输出进行本机短文本试验时，中文进度事件的墙钟时间减事件音频偏移约为 605–615 毫秒，英文约为 444–452 毫秒；英文 `4003` 再次产生四个相同原文范围的事件。墙钟从调用开始计算，包含初始化时间；这个差值不是经测量的设备播放延迟，也不能证明耳机中已经播放到的位置。试验没有捕获系统或用户的其他音频。
- 单独查询系统语音对象的运行状态时，在英文 `4003` 朗读期间，词语位置持续为 11、长度持续为 4，而报告的音素编号多次变化。这提供了比字符范围更细的状态线索，但尚无证据表明该编号能跨不同语音映射并从数字中间无缝续读；该试验没有更换项目所用引擎。
- 对两种英文系统语音使用内存音频朗读 `4003`，各收到 17 个口形事件，编号顺序相同但音频时间不同，且有不同编号对应同一时间的情况。对中文日期 `2026年3月8日`，本机慧慧桌面语音产生 32 个口形事件，本机小小语音产生 0 个。这个单机结果说明不能假设所有目标语音都提供该事件，也不能仅按事件序号证明跨语音无缝续读。
- 对 `2026` 与后续日期文字之间插入语音标记后，内存音频试验中，本机慧慧和小小语音均各返回一次标记事件，音频偏移分别为 1115 和 780 毫秒。说明这两种语音在该短句中能报告标记；尚未证明它不会改变数字的读法、能够准确对应设备中实际听完的位置，或能解决标记之前切换的问题。
- 在相同文本拼接方式下比较有无标记，每种条件各合成两次：慧慧无标记输出 121918 字节、有标记 124122 字节；小小分别为 82672 和 84330 字节。每种条件的两次输出摘要一致，而加标记后摘要及长度均变化。这表明标记会影响这两种语音在该输入下的音频输出，但单凭字节差异不能判断具体听感或是否改变了读法。
- 同一短句以两种方式各自重新合成后，对波形数据做逐字节前缀比较：慧慧前约 70.4 毫秒相同，而标记报告约在 1114.9 毫秒；小小前约 13.3 毫秒相同，而标记报告约在 688.2 毫秒。重复执行得到相同结果。两组音频在报告的标记之前已经不同；这不能量化听感差异，也不能推断它们之间的时间对齐关系。
- 试用带标记的提示构造器朗读 9 个字符的日期时，本机慧慧和小小语音返回的进度位置为 `82`、`104`、`105` 等，而不是相对原文的 `0` 至 `8`；不插入标记但仍使用该构造器时起点也为 `82`。这些偏移反映了生成的标记文本，并非当前播放控制器或网页映射可直接使用的原文偏移。若将来采用标记，必须设计并测试标记文本到原文的明确映射。
- 直接使用普通文本朗读同一日期时，本机慧慧报告 3 次进度事件，小小只报告 1 次；两者每次都覆盖原文 `0+9`。因此按事件次序跨两种语音对齐读音并不可靠，即使不引入标记也存在此问题。
- 在系统默认输出上直接调用语音合成器做三次中文语音切换：取消调用返回分别用时 136、98、174 毫秒，新语音首个进度事件分别在切换开始后 1042、617、651 毫秒到达。这是独立接口试验，未测量界面操作、设备中声音停止或实际听到新声音的时刻，也不能代表其他设备。

## 后续验证方向

先在隔离测试中研究本机语音输出的实际音频时钟、缓冲以及停止时的设备行为，并验证其与字符范围、展开读音的对应关系。必须同时覆盖中文、英文、数字和蓝牙设备。任何候选方案需保留原网页位置映射，实际测量切换延迟，并使用输出音频证据检查重复、缺失和重叠。未经验证，不调整既有播放核心，也不承诺达到精确无重复。
